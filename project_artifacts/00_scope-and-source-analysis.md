Пользовательская задача состоит из четырёх результатов:

1. Разобрать приложенное задание.
2. Создать отдельную папку с артефактами проекта.
3. Разбить исходное ТЗ на этапы и подготовить подробные технические спецификации с параметрами.

## 3. Что является проектным решением, а не прямой цитатой источника

- Основное production-хранилище: PostgreSQL; SQLite только для быстрых тестов.
- Чтение каналов: Telethon; пользовательский бот: aiogram 3.x.
- Для двух дополнительных заданий выбраны semantic deduplication и evals.
- Для LLM предусмотрен provider adapter, чтобы модель и провайдер задавались конфигурацией.
- Для workflow checkpointing нужен PostgreSQL-backed checkpointer; in-memory вариант допускается только в unit-тестах.
- Вводим явные статусы вакансии, заявки и workflow run, UUID в публичных идентификаторах и idempotency keys.

## 4. Границы первой версии

В MVP входят Telegram-источники, extraction, нормализация, дедупликация, scoring, digest, interrupt/resume, генерация ответа и безопасный `DRY_RUN`. В MVP не входят автоматическое исследование компаний, полноценный RAG по документам резюме, массовая рассылка и web-интерфейс.

## 5. Допущения, которые нужно подтвердить перед production

- Один владелец профиля и один Telegram-бот.
- Каналы доступны аккаунту Telethon и не требуют обхода ограничений Telegram.
- HR-контакт может быть username, ссылкой или отсутствовать.
- Вакансии и профиль содержат персональные данные; логи не должны хранить секреты и полный текст без политики retention.
- Порог релевантности по умолчанию — 70/100, но должен быть конфигурационным.
